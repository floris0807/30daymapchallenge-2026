# Day 15 — Inside out：足の下の星座（Planisphaerium Subterraneum）

日本の地下 約1,800 km に立ち、地表を見上げる。20 年分の震源（USGS、M4.5 以上、14,243 件）が深さの違う星になる。それを古い星図として描いた。ふつうの地図は上から見下ろすが、この地図は下から見上げる。だから星図と同じく、東が左に来る。

持ち帰ってほしい一文：**深い地震ほど西（日本海側）にあり、切ると斜めの一本線になる。**

- `index.html`：本体（単一ファイル。d3 と topojson-client を CDN から読む）
- `data.json`：震源のスナップショット（`[経度, 緯度, 深さ km, 規模, 年(小数), USGS id]`）。`fetch_data.py` で 1 回だけ取得した
- `land-50m.json`：Natural Earth の陸地 1:50m（world-atlas@2.0.2）
- `day15.png`：代表の静止画（1600×900、t=10、東北の停止中）
- `day15.mp4`：1 周 30 秒のループ動画（1600×900、H.264、yuv420p、30fps）

## 画面の読み方（一 → 二 → 三）
1. **一　見上げる**：円の中が、地下から見上げた天井（地表）。淡い砂色の帯が浅い震源で、日本列島に沿う天の川のように見える。金の星は中間の深さ、輪のついた氷色の星は深い震源。深い星は列島の右（西）の奥に散らばる。
2. **二　数える**：深さ 3 段ごとに、東経 140° より西にある割合を棒で示した。浅い段は 22%、中間は 35%、300 km より深い段は 74%。深いほど西へ寄る。
3. **三　切る**：朱の帯（幅 4°）が北から南へ動き、その帯の中の震源を、北から見た断面に打つ（東が左、西が右。円と同じ向き）。縦横は同じ縮尺。東北の帯では、70 km より深い震源が一列に並んで西へ下がる。直線を当てると約 27° になる。

## 限界
- 深さには震源決定の誤差がある。深さを決められず、固定値（10 km、35 km など）にされた記録を含む。浅い側の深さの細部は読めない
- M4.5 未満は含まない。深い地震は件数が少なく、20 年分の偏りを含む
- 傾きは、深さ 70 km 超の点への直線の当てはめで出した。東西に切った見かけの値で、板の正式な傾斜ではない。板が東西に対して斜めに沈む所（千島など）では、見かけの角度は小さく出る
- 「東経 140° より西」は経度で一本の線を引いた比較で、海溝からの距離ではない
- 円の中の星は遠近法で描いている。視点に近い深い星ほど外へずれて見える。円の中の 140° 線で 74% を数えることはできない（はしご図が正）

## 再現と撮影
- データの取り直し：`python3 -I fetch_data.py data.json`（USGS へ 1 回だけ問い合わせる。件数は事前に count で 14,243 件、上限 2 万件を確認済み）
- ページは静的配信で見る（`file://` では data.json を読めない）
- 静止画：`node tools/capture.mjs png "<URL>/day15-insideout/?shot" day15.png 1600 900 10`
- 動画：`node tools/capture.mjs frames "<URL>/day15-insideout/?shot" <frames> 1600 900 30 30` でコマを作り、tools/encode.sh の MP4 と同じ設定で書き出す：`ffmpeg -framerate 30 -i <frames>/frame_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 20 -preset slow -movflags +faststart day15.mp4`（encode.sh には GIF を止める切り替えがないため、MP4 の行だけを使った）
- `?shot` を付けると「動きを止める」ボタンを隠す。`window.__frame(t)` で時刻 t の絵を描く。フォントの読み込みと描画が済むと resolve し、通常の再生は止まる。絵は t だけで決まり、t=0 と t=30 は同じになる（PNG のハッシュ一致で確認）
- `prefers-reduced-motion: reduce` のときは、t=10（東北の停止）で止めて表示する

## 取り入れた技術
1. **地心直交座標の透視投影（lookAt）**：経度・緯度・深さを地球中心からの km 座標に直し、視点の前・右・上の軸に投影する。地下から北を上にして見上げると、right ＝ 前方 × 北 ＝ 西 になる。正しいカメラなら東西は自然に逆になるので、鏡像の処理は入れていない。
2. **d3 の球面クリップを透視投影に流用**：`d3.geoProjection(raw)` に自前の透視を渡し、`clipAngle(28)` で球面のまま切ってから描く。陸の塗りが裏返らず、視点の背後の点も出ない。注意点が 1 つある。d3 は作るときに `raw(0,0)` で中心を測り、平行移動に焼き込む。そのため raw は「見上げる点＝画面中心」からの相対座標で返し、`translate([CX, CY])` で戻している。
   ```js
   function ceilRaw(l, p) {
     const [lon, lat] = unrot.invert([l / rad, p / rad]);
     const s = project(ecef(lon, lat)) || [CX, CY];
     return [s[0] - CX, CY - s[1]];          // 中心からの相対で返す
   }
   const ceil = d3.geoProjection(ceilRaw).rotate([-138.5, -36.5]).clipAngle(28).scale(1);
   ```
3. **縦横同じ縮尺の断面と、画素で測る角度の検算**：断面の描画域は 570×190px（1600×900 のとき）。横 2,100 km、縦 700 km を、どちらも 1px ＝ 700/190 ≒ 3.68 km で描き、縦横をそろえた。200 km の L 字は縦横とも 54.3px。経度を帯の中央緯度で km に直し、x は東を左にした。当てはめ線の両端を画面の座標で測った角度は 26.889°。計算値 26.889° と一致した（表示は約 27°）。
4. **緯線と海岸線の交点で陸の区間を求める**：断面の地表で、帯の中央緯度が陸にかかる区間を太線にした。毎回 `geoContains` を何百回も呼ぶ代わりに、海岸線の線分と緯線の交点を数えて内外を切り替える。始点だけ `geoContains` で判定する。結果は緯度ごとにキャッシュしている。
5. **重ねの順と縁取りで白飛びを防ぐ**：加算合成をやめて普通に重ねた。中間と深い星は、藍の縁を描いてから塗る。浅い星は半径の上限を 1.8px、不透明度を .35 にした。深い星だけに白抜きの輪と淡い光芒を付けた。これで、色だけでなく形と明るさでも深さが読める。
