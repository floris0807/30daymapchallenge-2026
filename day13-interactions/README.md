# Day 13: Interactions — 風と波（日本近海）

その場の風が起こす波（風浪）と、遠くから届いたうねりのどちらが勝っているかを 1° 格子で示す地図。

## 再現手順
1. `python3 fetch.py`（標準ライブラリのみ。667 点 × 2 API、約 3 分）→ `data.json`
2. リポジトリのルートを http で配信し（例：`python3 -m http.server`）、`/day13-interactions/` を開く（file:// では data.json を読めない）
3. 投稿用の静止画と動画は `../../tools/` で撮る（`?shot=1` は操作 UI を隠し、動きを止め、左に凡例ぶんの余白を取る）
   - `node tools/capture.mjs png "http://127.0.0.1:8793/day13-interactions/?shot=1" day13.png 1600 900 0` → 1コマ目（t=0）の静止画
   - `node tools/capture.mjs frames "…?shot=1" <コマの置き場> 1600 900 30 6` → 30fps × 6 秒＝180 コマ
   - `sh tools/encode.sh <コマの置き場> day13` → `day13.mp4`、`day13.gif`、`day13-small.gif`

## 表現
- 点の色相＝判定、明るさ＝有義波高（0〜4 m、連続）。「波高のみ」ボタンで単一の配色に切り替え
- 判定式：`wind_wave_height > swell_wave_height` なら風浪優勢、それ以外（同値を含む）はうねり優勢
- 白い粒＝風。1° 格子の風を u・v 成分に分けて双線形補間した場を、粒が吹いていく向き（API の風向 +180°）へ流れる。速さは風速に比例（0.05 度/(kn・秒)、見やすさのための誇張で実際の速さではない）。経度方向は cos(緯度) で割り、メルカトルの画面上で風向どおりに進む
- 粒は陸に流さない：波が null の点を「陸」として同じく補間し、海らしさが下がると薄くし、0.35 未満で消える。生まれる位置も海の上に限る
- 点の脈動＝波の周期（`wave_period`）。6 秒のループを海の 24 秒（4 倍速）とみなし、脈動の回数を round(24 ÷ 周期) 回にした（今日のデータで 3〜9 回）。周期の長いうねりの海はゆっくり、短い風浪の海は速く脈打つ。回数を整数に丸めたのはループをつなぐため。振れ幅は半径の 82〜100% だけで、色（判定と波高）は変えない
- ループがつながる作り：絵は時刻 t だけで決まる（粒の状態を前のコマから持ち越さない）。粒の寿命は 1.5／2／3 秒（どれも 6 秒を割り切る）で、生まれと消えで透明になる。乱数は種を固定（mulberry32）。`window.__frame(t)` で任意の時刻を描ける
- 白い矢印（風の向きと風速）は、粒と重なって読みにくいので既定で隠した。「風の矢印」ボタンで出せる。出したときだけ風速の凡例を出す
- 「動きを止める」ボタンで止まる。`prefers-reduced-motion: reduce` の環境では最初から止まっている（粒は止まった1コマで見える）
- 「うねりの向き」ボタンで、うねりの進む向き（同じく +180°）を水色の細い矢印で重ねる
- 格子セルの塗りではなく点にした理由：背景スタイルに陸のポリゴンが無く、セルを塗ると沿岸で陸に被る。点の間から海岸線（水域ポリゴンの縁）が見えるようにした
- 背景は OpenFreeMap の `dark`（Positron と同じ配信元・読み込み方）。海図風に暗くするため

## データと出典
- Weather data by Open-Meteo.com（CC BY 4.0）。波：Marine API、風：Forecast API（10 m 風、kn）。いずれも `current` の値
- 波のモデル：既定の Best match。どのモデルが使われたかは応答に無く**不明**。返ってきた座標が約 1/12° 間隔で、ドキュメントにある MeteoFrance MFWAM（0.08°）と整合するが、確認はできていない
- 風のモデル：既定の Best match。モデル名は**不明**
- 点の位置は要求した 1° 格子。値は API が返した最寄りの格子点のもの（実座標は data.json の `wave_at` / `wind_at`）
